# CueDeck render core

Отдельное подключаемое ядро: очередь кадров, общий байтовый кэш, владение ресурсами,
приоритеты и протокол доставки. Electron остаётся панелью управления и хостом первого
backend. Постепенный вынос рендера в другой процесс не должен менять код получателей.

Пакет не импортирует Electron, DOM, PDF.js или файловую систему. В API нет canvas,
BrowserWindow, путей и объектов PDFDocumentProxy. Сборка проверяется без DOM/Node types;
полученный ESM можно загрузить обычным Node без браузера.

```sh
npm run build --prefix packages/render-core
```

## Контракт v1

| Часть | Обязанности |
| --- | --- |
| RenderBackend | Метаданные документа, render, dispose, capabilities и версия контракта |
| RenderKernel | Один scheduler/cache на backend, leases и отмена устаревших запросов |
| FramePortServer | По одному переданному буферу на получателя, отдельный бюджет доставки, ACK и поколения |
| FramePortClient | Получить и нарисовать кадр, вернуть буфер, отвергнуть устаревшее, обработать таймаут |
| Хост | Разрешённые immutable документы, выбор backend/процесса, порты, updateDocuments для сохраняемых ревизий, reset при смене backend и disconnect при закрытии |

Первый backend находится отдельно в [src/render-backends/pdfjs.ts](../../src/render-backends/pdfjs.ts).
Он работает с canvas/PDF.js в выделенном renderer, затем отдаёт собственные RGBA-пиксели. Смена backend делается через остановку
старого владельца и resume нового поколения с тем же контрактом. Нативный процесс пока
не реализован: готова граница для его подключения.

Формат доставки v1: RGBA8, transferable ArrayBuffer. GPU-текстуры добавляются отдельной
версией транспорта с собственным владением; zero-copy сейчас не обещаем. Таймер,
заметки, пользовательская компоновка суфлёра и финальная композиция выходов в ядро не входят.

Прототип с реальными Electron-процессами: [scripts/render-core-qa/](../../scripts/render-core-qa/).
Полный проект: [shared-slide-source.md](../../docs/design/shared-slide-source.md).


PDF-панели продукта подключены через [main host](../../src/main/shared-pdf.ts).
Next может удерживать готовый растр до перехода PGM; prefetch подготавливает его
без передачи RGBA. clear/cancel, закрытие и удаление документа снимают lease.
При заполнении кэша сервер снимает удержания подготовленных Next и повторяет
актуальный запрос; уже переданные пиксели сохраняются у получателей.
Продуктовый PDF-кадр ограничен1920×1080 независимо от Retina/DPI и4K-дисплеев.
Проверка настоящих панелей: [product-pdf-qa](../../scripts/product-pdf-qa/README.md).
