# Защита управления CueDeck из сети

Пункт появился в настройках **Внешнее управление** — «Защитить управление из сети». В CueDeck 0.12.0 и раньше его нет.

После обновления защита выключена. Старые подключения, кнопки и HTTP-порт работают как раньше. Если Companion запущен на том же компьютере, оставь адрес `127.0.0.1` или `localhost`: ключ ему не нужен.

## Как включить защиту для Companion на другом компьютере

Ключ лучше вставить в подключение **до** включения защиты — тогда ничего не потеряет связь на полпути.

1. Сначала обнови модуль CueDeck в Companion до новой версии. В существующем подключении CueDeck проверь IP компьютера с CueDeck и HTTP-порт, затем выбери новый модуль в **Module Version** и сохрани. Свои страницы поверх существующих импортировать не нужно: расставленные кнопки остаются.
2. В CueDeck открой ⚙ **Настройки → Внешнее управление** и нажми **«Скопировать ключ»** — CueDeck положит ключ в буфер обмена. Ключ можно скопировать и до включения защиты.
3. В подключении CueDeck в Companion вставь ключ в поле **«CueDeck access key / Ключ доступа CueDeck»** и сохрани подключение. Это нужно сделать один раз.
4. Вернись в CueDeck: включи управление **«Из сети»** и отметь **«Защитить управление из сети»**. Настройки применяются сразу.

Ключ состоит из 64 строчных букв `a–f` и цифр. Он сохраняется после перезапуска CueDeck и не меняется, пока его не пересоздать. Профиль площадки не переносит ключ на другой компьютер: там защиту и подключение нужно настроить отдельно.

Когда защита включена, ключ нужен для всех сетевых HTTP-запросов к CueDeck, включая получение состояния для кнопок Companion. OSC в этом режиме работает только на том же компьютере. Если нужен OSC по сети, оставь прежний режим без галочки защиты. Если снять галочку, сетевое управление снова работает как раньше.

## Другие кнопки и подключения

Для старых ссылок Generic HTTP и Elgato ключ можно добавить к адресу: `?key=КЛЮЧ`, а если в адресе уже есть `?value=…`, то `&key=КЛЮЧ`. Вместо параметра можно передать заголовок `Authorization: Bearer КЛЮЧ` — так делает обновлённый модуль Companion.

В Generic HTTP 3.1.1 заголовок задаётся в каждом действии, в поле **header input(JSON)**: `{"Authorization":"Bearer КЛЮЧ"}`. Передача заголовка и параметра `?key=` проверена в Companion 5.0.6. При неверном ключе подключение показывает `401`; после исправления снова работает.

Работу с настоящим Elgato в программе Stream Deck ещё не проверяли.

HTTP-ключ ограничивает доступ, но не шифрует передачу по сети. Используй его в доверенной локальной сети и не публикуй ссылки, в которых он указан.

## Если не подключается

| Что видно | Что проверить |
| --- | --- |
| `401` | Ключ в подключении Companion: скопируй его заново из настроек CueDeck. |
| `403` | Включено ли управление «Из сети». Запрос из браузера может быть отклонён отдельно. |
| Нет связи | IP компьютера с CueDeck, HTTP-порт и включено ли внешнее управление. |

Это ориентиры для проверки, а не гарантия причины каждой ошибки.

## Проверено

- macOS, Companion 5.0.6 на другом компьютере, тестовый модуль 0.3.1-auth.1: кнопки и состояние работают с ключом и без него, неверный ключ получает `401`.
- HTTP с другого компьютера: `Bearer` и `?key=`; без ключа `401`; OSC из сети при защите не действует.
- Перезапуск CueDeck: ключ сохраняется, Companion переподключается без повторного ввода.
- Generic HTTP 3.1.1 в Companion 5.0.6: Bearer, параметр `key`, неверный ключ, потеря и возврат связи. Старая кнопка без ключа работает при выключенной защите.
- Упакованный Windows x64 кандидат с Electron 44.7.2: native safeStorage, сохранение ключа после перезапуска, HTTP с другого компьютера и ограничения суфлёра.

Ещё не проверены настоящий Stream Deck из программы Elgato, Mac packaged с защитой и Windows-установщик. Windows-кандидат запускался отдельно, установленная программа не обновлялась.
