# Подключаемое ядро рендера CueDeck

Решение Азата 14 ноября 2026: Electron постепенно оставляем панелью управления. Первый этап: отдельный контракт ядра, PDF.js как backend и межпроцессный PDF-прототип. База `1c946f3`, ветка `work/shared-slide-source-20261114`.

## Граница ядра

| Часть | Реализация | Ответственность |
| --- | --- | --- |
| Ядро | [packages/render-core](../../packages/render-core/) | Очередь, отмена, кэш, leases, ACK и поколения |
| PDF.js backend | [pdfjs.ts](../../src/render-backends/pdfjs.ts) | Документ, растеризация, готовые RGBA-пиксели |
| Host adapter | [pdf-frame-prototype.ts](../../src/renderer/shared/pdf-frame-prototype.ts) | Источники, worker, Range и shutdown |
| Electron QA | [render-core-qa](../../scripts/render-core-qa/) | Отдельный владелец и renderer-получатели |
| Рабочий CueDeck | [shared-pdf.ts](../../src/main/shared-pdf.ts), [pdf-frame-client.ts](../../src/renderer/shared/pdf-frame-client.ts) | Оператор, суфлёр, зал и скрытый GPU-суфлёр получают RGBA одного владельца |

Ядро не импортирует Electron, DOM, PDF.js или файловую систему. Оно собирается в ESM и загружается обычным Node. Backend передаётся в `new RenderKernel(backend)`; позже его можно заменить proxy к отдельному процессу/нативной библиотеке. Нативный backend ещё не реализован, готова граница подключения.

Снимок зала не решает задачу Preview другого файла и следующего слайда. Полная перепись медиа сразу смешала бы несколько непроверенных изменений. Main, NDI и PowerPoint сейчас не объединяются.

## Контракт v1

Backend предоставляет `info` (apiVersion=1, id, formats), `describe(document)`, `render(key, signal)` и `dispose()`. Ядро предоставляет `request(consumerId, key, priority)`, `cancel(consumerId)` и `stop()`. Результат запроса: lease с frame/release либо null для отменённого запроса.

`key = { document, page, width, height, rotation, timeUs? }`. Document обозначает неизменяемую ревизию, не путь. Страницы начинаются с 1, размеры заданы в физических пикселях; DPR учтён вызывающей стороной. Rotation добавляется к повороту PDF-страницы. Static, timeUs=0 и другое время имеют разные ключи. PDF-backend отклоняет временные запросы: анимации ещё не подключены.

PGM, зал и текущий слайд суфлёра используют один полноразмерный растр страницы. Next заранее получает такой же растр следующей страницы. Размер карточки влияет только на CSS, без повторного рендера PDF. Preview другого файла остаётся отдельной ревизией. Суфлёр сохраняет таймер, заметки и компоновку. GIF, видео, звук и PowerPoint остаются в прежнем тракте.

QA читает только заданные файлы через capability URL. При чтении диапазона проверяются размер/mtime открытого файла. В продукте [реестр](../../src/main/shared-pdf-registry.ts) выдаёт capability URL двух активных ревизий. Размер и mtime проверяются при каждом Range; произвольный путь получатель передать не может.

## PDF, очередь и память

Максимум две ревизии имеют по одному PDFDocumentProxy/worker. Describe и render используют тот же документ. Уже начатая страница заканчивается; ненужные ожидающие страницы не попадают в worker. Обычная отмена не вызывает преждевременный RenderTask.cancel: его promise может завершиться до окончания декодирования в worker. Shutdown уничтожает loadingTask, включая открытый документ. Поздняя ошибка Range тоже уничтожает worker.

PDF.js получает чистый canvas context. Внешний save/clip до page.render давал белые/неполные страницы большого PDF в Chromium. Поля собираются после рендера копированием строк RGBA. Готовые пиксели считываются до cleanup, временный canvas обнуляется. Кэш владеет RGBA, получатели не зависят от decoded ImageBitmap PDF.js.

Для PDF от256МиБ сохраняется максимум одна декодированная страница на серию размеров. Она освобождается перед другой страницей или через300мс простоя. Размеры одной страницы повторно используют decode. Для малых документов остаётся прежний decoded reuse. PDF.js по-прежнему резервирует буфер размера файла; ядро уменьшает число копий, но не устраняет внутреннюю архитектуру PDF.js.

| Ограничение | Поведение |
| --- | --- |
| Очередь | Один активный render; program → preview → prefetch среди ожидающих, FIFO внутри приоритета |
| Отмена | Уходит конкретный потребитель; другим читателям кадр не отменяется |
| Кэш | Общий LRU по байтам; default128МиБ, в Electron QA96МиБ |
| Читатель | Одна lease на consumer; следующий запрос после release |
| Медленный читатель | Его кадры не уничтожаются; полный pinned cache возвращает backpressure |
| Размер | До8192px на сторону; кадр больше бюджета отклоняется |
| Освобождение | После последнего release; поздний результат при stop освобождается |

Бюджет кэша покрывает RGBA. Worker, decoded images, временный canvas/readback и compositor имеют дополнительную память. Последовательный render ограничивает временные поверхности одной строящейся страницей. Бюджет кэша не является пределом RSS/commit процесса.

## Доставка и смена владельца

FramePortServer/Client используют структурный интерфейс порта. В Electron порты передаются через MessageChannelMain; main не пересылает пиксели и не декодирует PDF. Другой транспорт подключается adapter-ом.

На получателя допускается один transferable ArrayBuffer без ACK и один слот последнего желаемого запроса. Глобальный бюджет доставки отдельный:64МиБ в QA. Копия создаётся после резервирования бюджета. Получатель рисует ImageData и возвращает allocation с ACK; stale frame не рисуется, но тоже возвращается. Ошибка рисования не забывает ACK. Закрытие/таймаут порта освобождают его учёт; у клиента есть таймаут ответа владельца.

При смене документов host вызывает pause, увеличивает поколение, останавливает старого владельца и resume нового. Поздний кадр прежнего поколения отвергается. Предыдущая картинка сохраняется до готовности новой. Пересозданный получатель подключается без повторного открытия неизменённого владельца.

Набор документов пока заменяется целиком. Дифференциальный реестр PGM/Preview и автоматическое восстановление owner после crash относятся к включению в рабочий CueDeck.

## Runtime и приёмка

| Среда | Статус |
| --- | --- |
| Node/ESM | Ядро собирается и работает без Electron |
| Mac Electron44.7.2 | Отдельные owner/получатели и оба PDF |
| Shuttle Windows x64 Electron44.7.2 | QA-программа без замены установленного CueDeck |
| Electron33/другие runtime | Не проверены; RGBA fallback предусмотрен контрактом |
| GPU-native transport | Пока не реализован; zero-copy не заявляется |

QA production-built, без dev/HMR; чужая dev не останавливается. Контроль использует реальный PdfLoader из1c946f3. Отдельный полный quality-проход сравнивает каждый кадр с независимым прежним загрузчиком. Совпадения нескольких получателей недостаточно: они могут разделить ошибку источника.

[Результаты и ограничения](shared-slide-source-results.md). Физический выход/Spout, таймер и заметки суфлёра в QA-программе не проверяются. Их приёмка требуется при включении ядра в рабочий продукт.


## Подключение продукта, 14 ноября

PDF и прежний PDF-результат конвертации используют общий owner по умолчанию.
Новые PowerPoint/NDI ветки не подключались. Диагностический CUEDECK_SHARED_PDF=0
возвращает прежние независимые PdfLoader. UI импортирует PDF.js только в этом режиме.
Выделенный owner имеет узкий preload без API управления приложением.

При смене Preview сохраняются документ и кэш PGM. Capability привязана к ревизии,
поэтому TAKE переносит уже открытый документ. Смена списка документов обновляет
метаданные портов, не меняя поколение неизменённых источников. Удалённые ревизии
отменяются и освобождаются после последней lease. Падение owner оставляет последний
нарисованный кадр, запускает восстановление и перезагрузку PDF-панелей; максимум
три попытки за минуту. Видео и таймер от этой перезагрузки не зависят.

Next готовится в физическом разрешении своего PGM и показывается уменьшенным.
При переходе используется тот же immutable key. Скрытый Next тоже готовится, но
без передачи пикселей. Растр Next удерживается lease до нового запроса, clear,
удаления документа или disconnect. Предзагрузка следующей страницы не копирует
пиксели в получателя. Кэш продукта192МиБ, транспорт128МиБ; бюджеты независимы.
Общий кадр вписывается в1920×1080 с сохранением пропорций страницы. Retina/DPI
и4K-дисплеи масштабируют показ, но не увеличивают PDF-растр. Даже после изменения размера
карточки PGM запрашивает прежний ключ. CSS вписывает страницу по актуальным размерам
контейнера в момент рисования, сохраняя дробную геометрию исходной страницы.
Существующие Syphon/Spout/OMT получают композицию через прежние выходные тракты.

[QA настоящего продукта](../../scripts/product-pdf-qa/README.md) работает собственной
production-копией, без dev/HMR и без замены установленного приложения.
